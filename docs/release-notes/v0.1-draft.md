# Replicera v0.1 Draft Release Notes

## Supported Environment

- Platforms: Linux x64 and Windows x64.
- Runtime: .NET 10 for framework-dependent packages; self-contained packages include the runtime.
- Destinations: SQL Server 2022, PostgreSQL 17, and Oracle AI Database Free 26ai, each validated with a Linux container image. Other versions are not yet certified.
- Source: Microsoft Dataverse through `Microsoft.PowerPlatform.Dataverse.Client` and `RetrieveEntityChanges`.
- License: Mozilla Public License 2.0 (`MPL-2.0`).

## Supported Type Mappings

| Dataverse value | SQL Server value |
| --- | --- |
| Unique identifier, lookup | `uniqueidentifier` |
| String | `nvarchar(n)` or `nvarchar(max)` |
| Memo/text | `nvarchar(max)` |
| Boolean | `bit` |
| Integer, choice/state/status | `int` |
| Big integer | `bigint` |
| Decimal, money | `decimal(p,s)` |
| Double | `float(53)` |
| Date only | `date` |
| User-local/time-zone-independent date-time | `datetime2(7)` |
| Multi-select choice | ordered numeric JSON in `nvarchar(max)` |

Polymorphic lookups add an `nvarchar(128)` companion column containing the target logical table name. Calculated and rollup values use their underlying supported type.

PostgreSQL maps the same neutral values to `uuid`, character/text, boolean, numeric, date, and timestamp types. Oracle maps them to `RAW(16)`, `NVARCHAR2`/`NCLOB`, `NUMBER`, `BINARY_DOUBLE`, `DATE`, and timestamp types. All providers preserve the ordered numeric JSON representation for multi-select choices and a companion target column for polymorphic lookups.

## Behavior

The CLI supports read-only inspection, initial and incremental synchronization, physical deletes, schema creation, nullable column addition, compatible widening, status reporting, and controlled full resynchronization. Jobs can use complete mirror, no-data-loss, or drop-and-recreate reload synchronization modes. Managed rows carry load timestamps, and no-data-loss rows carry source-removal timestamps. Destination rows, run metrics, and opaque checkpoints commit atomically. Matching unmanaged tables and incompatible schema changes are rejected; destructive propagation follows the selected synchronization mode. A credentialed Linux test validates account creation, update, and deletion through the complete Dataverse-to-SQL Server pipeline.

Per-table locks now cover schema reconciliation through checkpoint commit. Destructive DDL performs dependency preflight, missing Dataverse tables require direct confirmation, and explicit table-scoped column rename mappings preserve existing values.

Release builds use the `replicera` executable name and expose `--version`. Tag builds produce self-contained, versioned Linux and Windows archives with SHA-256 checksum files. Status output includes the latest run timing, operation counts, and sanitized errors.

## Known Limitations

- Certificate authentication configuration is implemented but has not been validated against a live Dataverse environment. Client-secret authentication is the live-validated method for v0.1.
- Linux client-secret authentication, opaque checkpoint round trips, invalid-checkpoint classification, and concurrent initial-feed mutations have been validated against non-production Dataverse. Naturally expired checkpoints and service-protection throttling still require live validation.
- The permission bootstrap creates an organization-wide reader role and assigns System Customizer. The steady-state application user has been validated without System Administrator through metadata updates, change feeds, and the complete Dataverse-to-SQL lifecycle.
- Retry behavior is owned by the adapter around `ServiceClient`: up to three retries honor Dataverse `Retry-After`, use bounded exponential fallback delays, propagate cancellation, and return sanitized typed errors after exhaustion.
- File, image, party-list, and other unsupported attribute types are reported but not replicated.
- Dataverse-to-SQL Server and Dataverse-to-Oracle have complete live create/update/delete evidence. PostgreSQL has live read-only account-feed evidence; its complete source lifecycle remains pending.
- Table filters, selected-column projections, label enrichment, scheduling, and a service mode are outside v0.1.
- Initial and full synchronization keep one SQL transaction open for the complete table and may block competing access.
- The CLI is prerelease software; configuration and command compatibility are not guaranteed before the final v0.1 tag.

## Upgrade Behavior

The destination metadata schema starts at version 1 and is created idempotently. Back up the destination database before upgrading. Future metadata migrations will be forward-only; downgrades are not supported. Never modify tables in the `replicera` schema or stored checkpoints manually.
